So the content respects the safe area and only the background and the top strip (city + globe, offset by `safeAreaInsets.top`) extend into it. Snapshots simulate the strip with `.safeAreaPadding(.top, 28)`.

It drives the user's real screen, so ask first: a run while the user was working sent keys elsewhere.

Found by changing one thing per build (ad-hoc ✗, development ✓, development without a `WidgetBundle` ✓). Not documented by Apple and no exact match found online; closest: macOS 27 refuses App Group containers to ad-hoc apps (github.com/frankydzoro/Limitwick/issues/8). Guarded twice: a "Require team signing" build step on the widget target and a signature check in `check.sh`.
  - Things that were not the cause (don't retry): optional parameter vs. `defaultResult()`, IDs containing `/`, the module name, the bundle ID. Apple's Clock app ships a "World Clock" widget whose extension is also `WorldClockWidget`, hence our "Minimal…" names.
  - The first development-signed install over an ad-hoc one still failed; a later one worked. A forum report says replacing a differently signed copy can leave stale widget state until `killall chronod`. After changing signing, remove and re-add the widget before judging.
  - `Text(date, style: .time)` draws a fixed time; a widget clock that updates itself needs `Text(.currentDate, format:)` (macOS 15+). And `Text(_:format:)` formats in the environment's `\.timeZone`, ignoring the format style's zone: `ZoneWidgetView` sets the environment. Snapshots of the Mac's own zone (Tokyo here) hide such bugs, so the widget snapshots include other zones.
  - Xcode 27 requires every `WidgetConfigurationIntent` parameter to be optional (Apple's "Making a configurable widget" sample with a non-optional one no longer builds).
  - Debugging the widget: `log show` returns nothing in the agent's shell, and a development-signed widget's container (`~/Library/Containers/com.jaredmarkowitz.minimalworldclock.widget`) can't be read by other processes, so a debug log file there only works for ad-hoc builds. Xcode registers the copy in `build/` too; `pluginkit -r <path to .appex>` unregisters it so only /Applications' copy is live. The app target's build prints "Metadata extraction skipped, no AppIntents.framework dependency found": harmless (`check.sh` filters it).
  - A `Window` scene containing a `Slider` opens 900 pt wide (the slider's ideal width); `frame(idealWidth:)` doesn't change that, `.defaultSize` on the scene does. macOS autosaves each window's frame in the app's defaults (`NSWindow Frame compare`), so delete that key (`defaults delete com.jaredmarkowitz.minimalworldclock "NSWindow Frame compare"`) before checking a default-size change. Don't run `defaults delete` on the whole domain: it wipes the saved zones too.
  - A slider with `step:` on macOS draws a tick per step (95 for quarter hours); `CompareView` rounds in the binding instead.
  - Scrubbing near a DST gap: the slider asks for 2:30 AM, the model resolves it to 3:30 AM (M2's rule), so the thumb jumps forward one hour. Intended.
  - System Events sees no windows until the app is activated (`tell application … to activate`); `CGWindowListCopyWindowInfo` sees them right away.
  - A SwiftUI app whose only scene is a `Window` quits when that window closes. `AppDelegate.applicationShouldTerminateAfterLastWindowClosed` returns `false`, and SwiftUI then reopens the `Window` on a Dock click by itself. Verified by script: close via System Events, then `open` the running app (sends a reopen event); count windows with `CGWindowListCopyWindowInfo`.
  - The ticker stops on `onDisappear` (window closed) but probably not when the window is minimized. M10's budget requires no timer activity then; check it there (e.g. `NSWindow.didMiniaturizeNotification` or `scenePhase`).
  - `DispatchTicker` uses `asyncAfter(wallDeadline:)`, which keeps counting while the Mac sleeps; `Timer` and `Task.sleep` use uptime clocks and would fire late after wake.
  - en_US time text has a narrow no-break space (U+202F) before AM/PM; tests use `nnbsp`. Time uses the `jmm` template, so 12/24 h follows the locale (en_GB → `21:00`) until M7.
  - `ImageRenderer` draws AppKit-backed controls (TextField, List, Slider) as yellow placeholders. The snapshot tool now draws through an offscreen `NSHostingView` + `cacheDisplay` instead.
  - The longest city name in the catalog is "Bahia Banderas" (`clock-long-name` snapshot).
  - `TimeZone.current.identifier` may not be in the known list (e.g. `Asia/Kolkata` vs. `Asia/Calcutta`); `ClockViewModel.live()` falls back to UTC then. If a user reports this, map through the catalog by matching zone data instead.
  - `swift test` prints "Test run with…" twice (once per test runner); that's normal.
  - A fresh clone needs `./scripts/setup.sh` once to install the git hook.
  - The system catalog uses old IANA names: `Asia/Calcutta` (not `Asia/Kolkata`), and `Etc/GMT±N` zones are not listed (only `GMT`). `zone(…)` in tests traps on unknown identifiers, so check names with `TimeZone.knownTimeZoneIdentifiers` first.
  - `TimeZone.abbreviation(for:)` returns `GMT+9`-style text for many zones (Tokyo included), so abbreviation search only helps for zones with real abbreviations (PST, CET…). That's why it's exact-match only.
  - `TimeZone(identifier:)` accepts abbreviations (`"PST"`) and resolves `"UTC"` to `"GMT"`; `knownTimeZoneIdentifiers` (443 on this Mac) lists `GMT` but not `UTC`. `Zone` validates against that list plus `UTC`.
  - Search sorts with `localizedStandardCompare`, so order follows the user's locale; tests compare against the same call rather than a hard-coded list.
  - `instant(for:)` samples the zone's offset around the wall time, keeps the candidates that read back as that wall time (earliest wins), and in a gap uses the smaller (pre-jump) offset. It doesn't use `Calendar.date(from:)`, whose gap and overlap behavior isn't documented.

## [x] M1: Zones and search
`Zone` (a validated IANA identifier with display `city` and `region`, Codable) and `ZoneCatalog` (every known zone, with search). Search ignores case and diacritics, treats `_` and space alike, and matches city, region, full identifier, or the abbreviation in effect on a given date (PST vs. PDT; exact match only). Cities that start with the query rank first, then alphabetical order.
