# Minimal World Clock

## Requirements
- Window with a clock that can be set to different time zones
- Window where you can easily and intuitively compare two different time zones
- Widget that shows the time for a specific time zone on the Mac desktop
- Accessible: works with screen readers (VoiceOver), for people with color blindness, and with the system's contrast and motion settings
- Lightweight and minimal: never affects the user's computer unexpectedly (low battery and CPU use, small size), and a minimal UI. Many world clock apps pile on features until they're hard to use; this one does the three things above and does them simply.
- A non-intrusive prompt asking users to buy the app, like the one planned for `~/Projects/pomodoro_timer` (its ROADMAP M13): the app stays fully usable either way.

## Technical requirements
- Built and designed by AI, so the repo is optimized for that (CLAUDE.md, a roadmap with tests as acceptance criteria, small files)
- TDD

## Decisions
- **Stack:** Swift 6 + SwiftUI. Shared `WorldClockKit` Swift package (Foundation-only logic in `WorldClockCore`, views and view models in `WorldClockUI`) with thin app and widget targets. Xcode project generated by XcodeGen. Tests use Swift Testing.
- **App shape (confirmed by the user):** a regular windowed app with a Dock icon (not menu bar only), since two of the three features are windows, including the Compare conversion tool. Clock and Compare are separate windows.
- **Time zones:** IANA identifiers from `TimeZone.knownTimeZoneIdentifiers`. The city shown is the last part of the identifier (`America/Argentina/Buenos_Aires` → "Buenos Aires"). Since M9 search also finds countries, zone names and cities that don't name a zone (below); localized names come later. `UTC` is accepted alongside the system's list; abbreviations (`PST`) are not valid zones.
- **Zone search:** ignores case and diacritics, treats `_` and space alike, and matches city, region or identifier by substring, or the abbreviation in effect on the given date by exact match only (many zones only have `GMT+9`-style abbreviations, so substring matches would flood the results). Cities starting with the query rank first, then city order.
- **Wider search (M9, decided with the user 2026-11-11):** search also matches a zone's country ("Japan", "United States" lists every US zone; nicknames like "UK", "USA", "Holland"), its zone names ("Pacific Time", "Central European"), and a bundled table of ~1,800 names (cities and alternate spellings) that don't name a zone ("San Francisco", "Osaka", "NYC", today's names like "Kolkata"), written by hand from public facts (no dataset, no credit needed). The user chose a large table with a size tier: major metros rank first. Order: the zone's own city exactly, then other exact names, then major cities starting with the query, then other cities starting with it, then everything else; each zone appears once, named for its best match. A row found through another city shows that city with the zone's city beneath ("San Francisco" / "Los Angeles · UTC−8"). Country codes come from the tz database's `zone.tab` (public domain) and names from Foundation, in English, precomputed by `scripts/make-zone-names.swift` (30 ms per process otherwise). Airports are out. The widget's edit screen uses the same search.
- **Picked city (M9, asked for by the user):** picking "San Francisco" shows San Francisco everywhere (Clock, Compare, VoiceOver, favorites, the widget), not Los Angeles: what's saved is a place (zone + city).
- **Favorites (M9, decided with the user):** a star appears on a hovered row (filled accent star for favorites; right-click, a VoiceOver action and ⌘D on the keyboard-highlighted row also toggle it). Favorites list first in their own section with a stronger line under it, then every zone (or the matching results while searching). A newly starred row stays put until the next search or opening. Saved in the App Group, so the widget's edit screen lists them first. A zone can be a favorite under several cities.
- **24-hour time (M9):** hours keep the locale's leading zero ("09:00", as macOS's menu bar clock does; the user chose this). Every view was checked in `en_GB` snapshots; no layout changes were needed.
- **Time math:** offsets read `UTC−5`, `UTC+5:30`, `UTC` and differences read `+9 h`, `−3 h 30 min`, `+15 min`, `Same time` (a typographic minus, hours always in hours, so Apia vs. Pago Pago is `+24 h`). A wall time skipped by a DST gap moves forward by the gap; a repeated one resolves to the first occurrence. Day relation is yesterday / today / tomorrow, plus a two-day case: zones 25 h apart (Kiritimati vs. Pago Pago) sit on dates two days apart for one hour each day.
- **Clock window (M3):** one zone, shown as the city name, the time in large type, and the date and UTC offset below. The city name is a button that opens the zone picker in a popover (search field + results with region and offset; Return picks the first result; a checkmark marks the current zone). Defaults to the Mac's zone, or UTC if the system reports a zone missing from its own list. Time follows the locale's 12/24-hour preference (since M7, unless Settings forces 12- or 24-hour). The chosen zone is saved in UserDefaults. A single `Window` scene, so there is only ever one Clock window. Closing it leaves the app running in the Dock; clicking the Dock icon reopens it.
- **Clock window design (M6, approved by the user 2026-11-10):** no title bar (close/minimize/zoom stay; drag anywhere to move). The city and a globe sit top-right, level with the window buttons, and together are the button that opens the zone picker. Below: the time in large light type with a smaller AM/PM, then the date. No UTC offset. Solid theme colors (no translucency): in the theme chosen in Settings (M7; Solarized light by default). The time and date scale with the window, and the window keeps the content's proportions while resizing, so it never fills with empty space; a new window opens at its natural size. Hovering the window turns the time to the accent color and draws a thin accent edge along the window; hovering the city/globe shows a soft accent pill. Dragging anywhere on the clock moves the window (the city/globe still opens the picker). The zone picker uses the theme's softer `surface` color (halfway between the window's background and white), the theme's text color, and the accent for the search field's ring and text cursor, the hovered row, and the checkmark; the scroll bar stays the system's (macOS can't recolor it without losing dragging). Tried and rejected: a translucent background, a globe alone in the corner, the city above the time with a chevron; for the picker, the full theme background (too heavy) and the plain system background (too white).
- **Color themes (decided by the user in M6, built in M7):** both windows and the widget use one color theme: background, text, and an accent for the city/globe. **The user picks a single theme** (2026-11-11: no "System" option and no light/dark pairing, "so it's not complicated"; a theme stays the same in Light and Dark mode, and a dark theme gives its windows macOS's dark controls). Default: Solarized Light. Sixteen themes, all asked for by the user: Solarized Light/Dark, Nord Light, Nord, Rosé Pine Dawn, Rosé Pine, Gruvbox Light/Dark, Navy on Cream, Cream on Navy, Paper, Dracula, and four retro video game looks the user asked for: LCD (an early handheld console's four greens; named for the screen, since "Pocket" was too close to "Game Boy Pocket"), Phosphor and Amber (CRT monitors), Arcade (neon). **Where the colors come from:** Solarized (Ethan Schoonover), Nord (Sven Greb), Rosé Pine, Dracula and Gruvbox (Pavel Pertsev) are MIT-licensed palettes, credited in the About window (`Apps/Mac/Credits.rtf`, asked for by the user; Gruvbox has no LICENSE file, its README says MIT/X11, so it's credited by author without a copyright line). Names: kept as the palettes' own (descriptive use with credit; the user decided 2026-11-11 to keep "Dracula" despite its creator's claimed trademark, and to rename or remove it if asked). Which palette color plays background, text and accent is our choice (Solarized Dark uses the brighter base1 text; Rosé Pine Dawn the pine accent, its rose being too faint). The rest are plain color choices with no palette to credit: Navy/Cream (ours), Paper (white, Apple's #1C1C1E and Tailwind's MIT-licensed orange-700 #C2410C), Phosphor and Amber (common approximations of P1 and P3 phosphor), LCD (the widely shared approximation of the console's screen), Arcade (typical synthwave colors; not traced to a specific palette, can be nudged if wanted). Every theme passes WCAG AA (M8; four accents were nudged, see Accessibility below).
- **Settings (M7, layout "B" chosen by the user from an option sheet):** the standard macOS Settings window (⌘,, system look, not themed): Time (System / 12-hour / 24-hour, segmented), Open at login (`SMAppService.mainApp`; macOS keeps the state), and Theme as a grid of swatches (selected: ring and checkmark). Changes apply at once to both windows; the widget follows within seconds (macOS schedules widget reloads; measured 5–10 s by the user, left as is). **No "Show seconds"** (dropped by the user: not needed, and jarring on the Clock). The widget reads the theme and 12/24-hour choice from an App Group shared with the app (team-ID-prefixed `Y7W4DC22F6.com.jaredmarkowitz.minimalworldclock`: no provisioning profile, no "access data from other apps" prompt; confirmed by the user).
- **Compare window design (M6, chosen by the user 2026-11-10 as option "H" from two rounds of option sheets):** the Clock window's look (no title bar, the chosen theme, drag the background to move, thin accent edge on hover). Each zone: city + globe (zone picker), the time, the date; B's date adds its day relative to A's when they differ (`Friday, January 16 · next day`; nothing on the same day). Between them: the difference in the accent (`+14 h`) above the swap button. Below: a drawn 24-hour strip (hour ticks, labels every 6 h, accent fill and thumb; hovering it darkens and thickens the track (gray and accent), rings the thumb, and shows a thin line at the quarter hour a click would jump to, and the swap button shows a soft accent circle on hover, both asked for by the user) instead of the system slider, which ignores the theme's tint on macOS. "↩ Now" is a pill in the title bar strip, top-right, shown only while scrubbed. **Typing a time (requested by the user in M6):** click either time to type one (`9`, `9:30 pm`, `21:30`); hovering a time shows an accent background and the text cursor. Return commits (unreadable input beeps and stays open), Esc cancels, and clicking elsewhere keeps a typed time or quietly goes back to the shown one (asked for by the user). Without AM/PM, a 12-hour locale keeps the shown time's half of the day ("5" over 3 PM → 5 PM); hours 13–23 are always 24-hour. Typing B's time keeps B's shown date, and A follows (it may change day). **Resizing (asked for by the user in M6):** like the Clock window, everything but the Now pill scales with the window and the window keeps the content's proportions; the natural size assumes two-digit hours, so the text doesn't change size while scrubbing; a new window opens at its natural size. Rejected: a chevron after the city, split halves, both cities' hours on the strip, stacked rows, the system slider.
- **Compare window behavior (M4):** two zones side by side, the difference and day relation (labels `Same day`, `Next day`, `Previous day`, `2 days later/earlier`), and a scrubber over zone A's day (midnight to 11:45 PM, snapping to quarter hours) with "Now". Scrubbing fixes a wall time in A on the day A was on when scrubbing began; it stays put as real time passes until "Now". Swapping keeps the instant shown (the slider moves to the new A's reading); changing A while scrubbed keeps the slider's reading (3 PM stays 3 PM); changing B keeps the instant. Both zones are saved (separate keys, so one unreadable zone doesn't lose the other); the scrub isn't. Defaults: the Mac's zone (A) and UTC (B). Window menu: Clock ⌘1, Compare ⌘2; the Compare window opens 640 pt wide.
- **Widget (M5):** WidgetKit, small and medium. The zone is chosen in the widget's own edit screen (App Intents parameter with search over the same catalog as the zone picker; suggestions list every zone by city; a new widget shows the Mac's zone, or UTC), so the zone needs no shared storage (M7 adds an App Group for the Settings choices only). Shows the city, the live time (12/24 h by locale), and the date (M5 also showed the UTC offset in medium; M6 replaced the look, see Widget design below). The time updates itself; the timeline only refreshes at the zone's next midnight, noon (AM/PM, since M6), DST change, or when the hour gains or loses a digit (since M6, for centering).
- **Widget design (M6, chosen by the user 2026-11-10 over several option sheets):** Solarized background (light or dark with the Mac), city in the accent, time in the light weight with a smaller AM/PM (42 pt small, 56 pt medium, enlarged at the user's request), no UTC offset (the windows dropped it too). **Medium** has the Clock window's look: city top-right, time and date centered (`Thursday, January 15`). **Small** stacks city and date (`Thu, Jan 15`) top-left with the time bottom-left ("like the Apple Watch", said the user). A 1.5 pt border in the text color, 6 pt in from the edge (not the accent, which means hover in the windows): macOS draws its own light line along the top and bottom of every desktop widget, so a border on the edge looked like a gap; set in, the space reads as deliberate. AM/PM is a separate fixed `Text`, and the live hours and minutes are drawn over a hidden fixed copy, both refreshed by the timeline: on the desktop a live `Text` takes all the width it can, and a custom format leaves the widget on its placeholder. Rejected: centered city on top, city and date on one line, a split medium, borders on the edge or in the accent.
- **Bundle ID (changed 2026-11-10 in M5, approved by the user; nothing released yet):** `com.jaredmarkowitz.minimalworldclock`, widget `com.jaredmarkowitz.minimalworldclock.widget` (permanent once on the App Store). Was `com.jaredmarkowitz.worldclock`; renamed with the widget so every name matches "Minimal World Clock" (Apple's Clock app already has a "World Clock" widget).
- **Signing (M5):** every build, local ones included, is signed with the Apple Development certificate (team Y7W4DC22F6). Ad-hoc signed, the widget appears but can't keep its configured zone. The build fails rather than produce an ad-hoc widget.
- **Lightweight (budget confirmed by the user):** no third-party dependencies; the clock ticks once a minute (no seconds display); no background work when nothing is visible (App Nap allowed, timers paused for hidden windows); budgets checked in M10 (ROADMAP.md): bundle under 10 MB, idle CPU near 0%, Energy Impact low, memory under 50 MB. **Met in M10** with no fixes needed (README → Lightweight budget: 7.6 MB universal, 0% idle CPU, 29 MB). A window pauses its ticking whenever it can't be seen (minimized, fully covered, on another Space, the app hidden, the display asleep), not only when closed, and catches up the moment it shows again.
- **App icon (M10, design "G" chosen by the user from an option sheet of eight):** a cream dial on a navy rounded square, hands at 10:10, the hour hand navy and the minute hand orange. Drawn by `scripts/make-icon.swift` from plain shapes (no SF Symbols: Apple's license forbids them in icons) on Apple's macOS icon template, so macOS 26+ shows it in its own shape with no gray tile (checked on macOS 27; an Icon Composer `.icon` isn't needed). The cream (#FDF6E3) and orange (#CB4B16) are Solarized's (MIT, credited in About); the navy (#1B2A4A) is ours. Offered and not chosen: the same icon in the Cream on Navy theme's own colors (no outside palette). Rejected: a plain or globe-lined dial on cream or blue, two overlapping clocks (muddy at 16 px), a day/night dial, a thin dial on Solarized Dark, a globe with one hand.
- **Version 1.0.0 (M10).**
- **Minimal UI:** each window shows only what its job needs. New features, options and settings need a clear reason from the requirements; when in doubt, leave it out. Prefer one obvious way to do something over several configurable ones.
- **Menu bar:** the Compare window (Window → Compare, ⌘2) and Settings (⌘,, M7) are reached from the menu bar; the windows themselves carry no buttons for them.
- **Widget speed (M6):** the pause when opening the zone list in the widget's edit screen is macOS's (Apple's own World Clock widget behaves the same); the edit screen keeps listing every zone.
- **Visual design:** iterated with the user in a dedicated pass (ROADMAP M6) once the Clock and Compare windows and the widget exist, before Settings, so earlier milestones keep visuals plain. The same pass covers UI speed (added by the user 2026-11-10): the windows, picker and scrubber should feel instant.
- **Color blindness:** color is decoration only. Every state also has text or a symbol, and views are checked with the macOS color filters (M8).
- **Accessibility (M8, decided with the user 2026-11-11):** WCAG AA for every theme (4.5:1 for text, 3:1 for marks and focus indicators), checked by tests. Four accents failed and were nudged within their hue (the user chose this over keeping the palettes' exact colors, and asked that it be noted in About, `Apps/Mac/Credits.rtf`): Solarized Light #268BD2 → #1F70AA, Solarized Dark #268BD2 → #3E9BDC (and its text #93A1A1 → #95A2A2), Nord Light #5E81AC → #4A6A90, LCD #306230 → #224522. Hover fills behind text went from 15% to 6% (chosen by the user from an option sheet); "↩ Now" became a solid accent pill with the text in the background color (chosen by the user); secondary text (strip hour labels, picker details) is solid, not faded. Keyboard: Tab reaches Compare's times (solid accent ring; Return or Space types) and the strip (arrow keys); the zone picker takes ↓/↑ and Return; the buttons follow macOS's Keyboard navigation setting. Increase Contrast strengthens faint lines and rings; Reduce Motion turns hover fades off; no translucent materials are used, so Reduce Transparency changes nothing. VoiceOver reads whole sentences ("Paris is 8 hours behind Tokyo"; the strip says both zones' times).
- **Minimum macOS (changed 2026-11-10, confirmed by the user):** 15 (Sequoia). Was 14 (Sonoma, the first with desktop widgets), but a widget clock that updates itself needs `Text(.currentDate, format:)`, new in macOS 15; on 14 it would need a timeline entry per minute. iOS minimum follows: 18.
- **Supporter unlock (decided 2026-11-10):** mirror pomodoro_timer's M13 as closely as possible. v1.0 ships free with no reminder; in an update, every feature stays free and a gentle once-a-day reminder (a small card inside the Clock window, starting after a few days of use, never on first launch, one-click "Not now") asks people to buy a one-time in-app purchase (StoreKit 2, non-consumable) that removes it for good, with Restore Purchase. No feature paywall. Price to be decided by the user later. Scheduled as M12.
