# Minimal World Clock

## Requirements
- Window with a clock that can be set to different time zones
- Window where you can easily and intuitively compare two different time zones
- Widget that shows the time for a specific time zone on the Mac desktop
- Accessible: works with screen readers (VoiceOver), for people with color blindness, and with the system's contrast and motion settings
- Lightweight and minimal: never affects the user's computer unexpectedly (low battery and CPU use, small size), and a minimal UI. Many world clock apps pile on features until they're hard to use; this one does the three things above and does them simply.
- A non-intrusive prompt asking users to buy the app, like the one planned for `~/Projects/pomodoro_timer` (its ROADMAP M13): the app stays fully usable either way.

## Technical requirements
- Built and designed by AI, so the repo is optimized for that (CLAUDE.md, a roadmap with tests as acceptance criteria, small files)

## Decisions
- **Stack:** Swift 6 + SwiftUI. Shared `WorldClockKit` Swift package (Foundation-only logic in `WorldClockCore`, views and view models in `WorldClockUI`) with thin app and widget targets. Xcode project generated by XcodeGen. Tests use Swift Testing.
- **App shape (confirmed by the user):** a regular windowed app with a Dock icon (not menu bar only), since two of the three features are windows, including the Compare conversion tool. Clock and Compare are separate windows.
- **Time zones:** IANA identifiers from `TimeZone.knownTimeZoneIdentifiers`. The city shown is the last part of the identifier (`America/Argentina/Buenos_Aires` → "Buenos Aires"). City aliases and localized names come later. `UTC` is accepted alongside the system's list; abbreviations (`PST`) are not valid zones.
- **Zone search:** ignores case and diacritics, treats `_` and space alike, and matches city, region or identifier by substring, or the abbreviation in effect on the given date by exact match only (many zones only have `GMT+9`-style abbreviations, so substring matches would flood the results). Cities starting with the query rank first, then city order.
- **Time math:** offsets read `UTC−5`, `UTC+5:30`, `UTC` and differences read `+9 h`, `−3 h 30 min`, `+15 min`, `Same time` (a typographic minus, hours always in hours, so Apia vs. Pago Pago is `+24 h`). A wall time skipped by a DST gap moves forward by the gap; a repeated one resolves to the first occurrence. Day relation is yesterday / today / tomorrow, plus a two-day case: zones 25 h apart (Kiritimati vs. Pago Pago) sit on dates two days apart for one hour each day.
- **Clock window (M3):** one zone, shown as the city name, the time in large type, and the date and UTC offset below. The city name is a button that opens the zone picker in a popover (search field + results with region and offset; Return picks the first result; a checkmark marks the current zone). Defaults to the Mac's zone, or UTC if the system reports a zone missing from its own list. Time follows the locale's 12/24-hour preference until M7 adds the setting. The chosen zone is saved in UserDefaults. A single `Window` scene, so there is only ever one Clock window. Closing it leaves the app running in the Dock; clicking the Dock icon reopens it.
- **Clock window design (M6, approved by the user 2026-11-10):** no title bar (close/minimize/zoom stay; drag anywhere to move). The city and a globe sit top-right, level with the window buttons, and together are the button that opens the zone picker. Below: the time in large light type with a smaller AM/PM, then the date. No UTC offset. Solid theme colors (no translucency): Solarized light in Light mode and Solarized dark in Dark mode, following the Mac's appearance (the start of the "System" default). The time and date scale with the window, and the window keeps the content's proportions while resizing, so it never fills with empty space; a new window opens at its natural size. Hovering the window turns the time to the accent color and draws a thin accent edge along the window; hovering the city/globe shows a soft accent pill. Dragging anywhere on the clock moves the window (the city/globe still opens the picker). The zone picker uses the theme's softer `surface` color (halfway between the window's background and white), the theme's text color, and the accent for the search field's ring and text cursor, the hovered row, and the checkmark; the scroll bar stays the system's (macOS can't recolor it without losing dragging). Tried and rejected: a translucent background, a globe alone in the corner, the city above the time with a chevron; for the picker, the full theme background (too heavy) and the plain system background (too white).
- **Color themes (decided by the user in M6, built in M7):** windows use a color theme: background, text, and an accent for the city/globe. Themes follow well-known palettes (Solarized, Nord, Dracula, Rosé Pine, classic print combinations such as navy & cream); the default follows the system's light/dark mode, and Settings offers the others. Every theme must pass M8's contrast checks.
- **Compare window (M4):** two zones side by side (each a `TimeDisplay` whose city name opens the zone picker), a swap button between them, a line with B's difference and day relation (`Tokyo +14 h · Next day`; labels `Same day`, `Next day`, `Previous day`, `2 days later/earlier`), and a slider over zone A's day (midnight to 11:45 PM, snapping to quarter hours) with a "Now" button, disabled while live. Scrubbing fixes a wall time in A on the day A was on when scrubbing began; it stays put as real time passes until "Now". Swapping keeps the instant shown (the slider moves to the new A's reading); changing A while scrubbed keeps the slider's reading (3 PM stays 3 PM); changing B keeps the instant. Both zones are saved (separate keys, so one unreadable zone doesn't lose the other); the scrub isn't. Defaults: the Mac's zone (A) and UTC (B). Window menu: Clock ⌘1, Compare ⌘2; the Compare window opens 640 pt wide.
- **Widget (M5):** WidgetKit, small and medium. The zone is chosen in the widget's own edit screen (App Intents parameter with search over the same catalog as the zone picker; suggestions list every zone by city; a new widget shows the Mac's zone, or UTC), so no App Group or shared storage is needed. Shows the city, the live time (12/24 h by locale), and the date: `Thu, Jan 15` in small, `Thursday, January 15 · UTC+9` in medium. The time updates itself; the timeline only refreshes at the zone's next midnight or DST change. Plain look until the M6 design pass.
- **Bundle ID (changed 2026-11-10 in M5, approved by the user; nothing released yet):** `com.jaredmarkowitz.minimalworldclock`, widget `com.jaredmarkowitz.minimalworldclock.widget` (permanent once on the App Store). Was `com.jaredmarkowitz.worldclock`; renamed with the widget so every name matches "Minimal World Clock" (Apple's Clock app already has a "World Clock" widget).
- **Signing (M5):** every build, local ones included, is signed with the Apple Development certificate (team Y7W4DC22F6). Ad-hoc signed, the widget appears but can't keep its configured zone. The build fails rather than produce an ad-hoc widget.
- **Lightweight (budget confirmed by the user):** no third-party dependencies; the clock ticks once a minute unless seconds are shown; no background work when nothing is visible (App Nap allowed, timers paused for hidden windows); budgets checked in M9 (ROADMAP.md): bundle under 10 MB, idle CPU near 0%, Energy Impact low, memory under 50 MB.
- **Minimal UI:** each window shows only what its job needs. New features, options and settings need a clear reason from the requirements; when in doubt, leave it out. Prefer one obvious way to do something over several configurable ones.
- **Menu bar:** the Compare window (Window → Compare, ⌘2) and Settings (⌘,, M7) are reached from the menu bar; the windows themselves carry no buttons for them.
- **Widget speed (M6):** the pause when opening the zone list in the widget's edit screen is macOS's (Apple's own World Clock widget behaves the same); the edit screen keeps listing every zone.
- **Visual design:** iterated with the user in a dedicated pass (ROADMAP M6) once the Clock and Compare windows and the widget exist, before Settings, so earlier milestones keep visuals plain. The same pass covers UI speed (added by the user 2026-11-10): the windows, picker and scrubber should feel instant.
- **Color blindness:** color is decoration only. Every state also has text or a symbol, and views are checked with the macOS color filters (M8).
- **Minimum macOS (changed 2026-11-10, confirmed by the user):** 15 (Sequoia). Was 14 (Sonoma, the first with desktop widgets), but a widget clock that updates itself needs `Text(.currentDate, format:)`, new in macOS 15; on 14 it would need a timeline entry per minute. iOS minimum follows: 18.
- **Supporter unlock (decided 2026-11-10):** mirror pomodoro_timer's M13 as closely as possible. v1.0 ships free with no reminder; in an update, every feature stays free and a gentle once-a-day reminder (a small card inside the Clock window, starting after a few days of use, never on first launch, one-click "Not now") asks people to buy a one-time in-app purchase (StoreKit 2, non-consumable) that removes it for good, with Restore Purchase. No feature paywall. Price to be decided by the user later. Scheduled as M11.
