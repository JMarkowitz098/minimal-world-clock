# M5: Desktop widget

A WidgetKit extension (`MinimalWorldClockWidget`, small and medium sizes) showing the time in one zone, chosen when the user edits the widget (`AppIntentConfiguration` with a zone parameter backed by `ZoneCatalog`). As built: the time updates on its own via `Text(.currentDate, format:)` (macOS 15+, so the minimum moved to 15; `Text(date, style: .time)` doesn't tick), so the timeline only refreshes on day and DST changes. Builds must be signed with a development team: ad-hoc signed, macOS drops the picked zone.
- Tests: the zone entity query (search, default), timeline entry dates (next midnight, next DST transition), and widget display strings. As built: Core `nextDisplayChangeIsNextMidnightInZone`, `nextDisplayChangeIsStrictlyAfterNow`, `nextDisplayChangeIsDSTTransitionWhenSooner`, `nextDisplayChangeAfterTransitionIsMidnight` (renamed `…UsesTheNewOffset` in M6 when noon became a change), `midnightSkippedByDSTMovesToTheTransition`, `displayChangesListsSuccessiveChanges`, `systemZoneUsesItsIdentifier`, `unlistedSystemZoneFallsBackToUTC`, `zoneQueryResolvesIdentifiers`, `zoneQuerySearchMatchesCatalogSearch`, `zoneQuerySuggestsEveryZoneByCity`, `zoneQueryDefaultIsTheMacZone`; UI `widgetDisplayStringsAtFixedInstant`, `widgetTimeFollowsTwentyFourHourLocale`, `widgetDateFollowsTheZone`, `widgetOffsetAtTransitionIsTheNewOffset` (removed in M6 with the widget's UTC offset); `check.sh` fails if the app or widget has no team ID.
- Done when: tests pass; installed from /Applications, the widget appears in the macOS widget gallery, can be placed on the desktop, and shows the chosen zone's time.
- Risk (happened): ad-hoc signing let the widget appear but not keep its zone; fixed with development signing (README → Testing locally).

**Calls made without asking** (the user can revisit them): a new widget shows the Mac's zone until edited; the edit screen's zone field starts empty.
