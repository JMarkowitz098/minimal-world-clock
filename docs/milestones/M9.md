# M9: Pre-release features

Features the user wants before 1.0 (decided 2026-11-10): wider zone search, favorite zones, and 24-hour clock support. Search and favorites live in Core (search, favorites storage) with the picker as their only UI. Keep the picker minimal: no new windows or settings for any of them.
- **Zone search** (moved from Later by the user, 2026-11-10): the zone picker and the widget's edit screen find a zone by what people type, not only by the city the IANA identifier names. Dateful's converter is the bar (the user's favorite; it finds "Japan", "Pacific Time", small cities, airports). Matches: countries (`Japan` → Tokyo; a country with several zones lists them all), common zone names (`Pacific Time`, `Eastern`, `Central European`, from `TimeZone.localizedName(for: .generic…)` where it covers them), and major cities that don't name a zone (`San Francisco` → Los Angeles, `Boston` → New York, `Osaka` → Tokyo) from a small bundled table in Core. A result found through an alias shows what matched (e.g. `San Francisco` with `Los Angeles · UTC−8`). Existing ranking stays: exact and prefix matches first. Decide with the user how far the city table goes (a few hundred major cities, not a gazetteer) and keep it within the bundle budget. Airports are out unless the user asks.
- **Favorite time zones** (requested by the user in M6): mark zones as favorites in the zone picker; favorites list first, above search results (and as the whole list when the search is empty, if the user agrees). Decide with the user how a zone is marked (e.g. a star on hover) and whether the widget's edit screen suggests the favorites. Favorites are saved with lenient decoding (an unknown zone is dropped, not the whole list).
- Tests (Core, fixed dates): `searchMatchesCountryName`, `countryWithSeveralZonesListsEach`, `searchMatchesGenericZoneName`, `searchMatchesCityAlias`, `aliasResultNamesTheMatchedCity`, `exactCityRanksBeforeAlias`, `aliasSearchIgnoresCaseAndDiacritics`, `zoneQuerySearchUsesAliases` (widget edit screen); plus a snapshot of the picker showing an alias result.
- Tests (favorites): `favoritesListFirst`, `favoritesKeepTheirOrder`, `togglingFavoriteAddsAndRemoves`, `favoritesRoundTripThroughStore`, `unknownFavoriteIsDroppedOnDecode`; view model tests for the picker's rows; snapshots of the picker with favorites and with an alias result.
- **24-hour clock** (added by the user, 2026-11-10): every view works in 24-hour time (`21:00`, no AM/PM): Clock and Compare times, typed times in Compare, the strip's hour labels, the widget (small and medium), and the zone picker's offsets. Much already follows the Mac's locale (tests: `twentyFourHourLocaleShowsTwentyFourHourTime`, `scrubberMarksFollowTwentyFourHourLocale`, `typedTimeInTwentyFourHourLocale`, `widgetTimeFollowsTwentyFourHourLocale`, `zeroPaddedTwentyFourHourTimeAddsNoEntries`); this checks the rest end to end: layouts sized for 24-hour text (e.g. Compare's `widestTime` with `23:45`, the widget with no AM/PM), and the Mac's own 24-hour setting (System Settings → General → Date & Time) followed without a relaunch (M7 rebuilds the formatters on `NSLocale.currentLocaleDidChangeNotification`; not yet checked in the running app, checked by the user in M9). M7's 12/24-hour setting is the user's override; M7 also covered the windows and the widget switching live, so check here only what's left. Ask the user whether the 24-hour hour has a leading zero (`09:00` vs `9:00`; the locale decides today).
- Tests (24-hour): `widestTimeInTwentyFourHourLocale`, `compareTimesInTwentyFourHourLocale`, `formattersFollowALocaleChange`; snapshots of the Clock, Compare and both widgets in `en_GB`.
- Done when: searching `Japan`, `Pacific Time` and `San Francisco` finds the right zone in the picker and the widget's edit screen, and favorites list first in the picker and survive relaunch, and with the Mac set to 24-hour time every view shows 24-hour time without AM/PM, laid out without clipping.
- As built (2026-11-11, checked by the user): search as above with a ~1,800-name city table (the user chose a large table with a "major" tier ranked first) and English country and zone names generated into `ZoneNames.swift`; a picked city is kept (`Place`, asked for by the user after trying it: "San Francisco" shouldn't turn into Los Angeles), in both windows, favorites and the widget; favorites: star on hover, their own section first, saved in the App Group, first in the widget's edit screen; 24-hour needed no code changes ("09:00" kept).
